## Confirmed defects and fixes

### VMS-EXT-001 — High — unsafe Windows installer recovery parity

- Reproduction: inspect or execute `scripts/install.ps1` with an existing fixed `$Destination.rollback`; the script deleted it before replacement. Regular-file and reparse-point destinations/ancestors were not rejected, no unique backup or metadata was created, and the native script was absent from CI.
- Root cause: the Windows script predated the transactional safety contract implemented by the Python and Unix installers.
- Fix: destination/ancestor reparse checks, target-type validation, unique backup names, metadata sidecars, orphan preservation/refusal, staging, rollback-safe recovery, and matching uninstall refusal. `scripts/test-install.ps1` exercises the real scripts on Windows.

### VMS-EXT-002 — Medium — sandbox state override did not relocate locks

- Reproduction: run offline `doctor` from a Codex workspace sandbox with `VENICE_MEDIA_STATE_DIR` under the writable project or temporary root. It timed out trying to create the consent lock under platform-global Application Support.
- Root cause: `_LOCK_DIR` was resolved from platformdirs at module import instead of deriving from the configured state file.
- Fix: default lock paths now use `<state-file-parent>/locks`; `VENICE_MEDIA_LOCK_DIR` remains an explicit override. A regression test verifies the derived path.
